## P1: bugs (things that look broken)
1. **Footnote popover runs off the screen on phones.** Opening a ⊞ note at 390 wide pushes the page to
   509px (horizontal scroll) and the text is cut. Clamp it inside the viewport (left/right 16px), or on small
   screens show the note inline under the paragraph. Close on outside tap and Escape.
2. **CLI verb ring is broken.** Desktop: the ring/edges connecting the six verbs are almost invisible, so it
   reads as 6 loose boxes. Phone: only some nodes render and the ring is cut (`m-top.png`, 3rd column).
   Draw a clearly visible loop (arrows in order context → branch → try → check → request → report → back),
   keep the active-verb highlight, and give phones a layout that fits (smaller ring or a vertical list).
3. **The setup prompt is cut off.** In the "Setup prompt" code block every line runs off the right edge on all
   widths. It's the most important text on the site: wrap it (`white-space: pre-wrap`) so the whole prompt is
   readable without scrolling.
4. **Coverage table on phones:** the Delete column is cut off, and rows have big uneven gaps. Below ~640px turn
   each row into a compact stacked item: type name, then add / modify / delete pips (reuse the figure's pip
   style), then the note.
5. **CLI "Setup, loop and rules" table on phones:** commands break mid-word (`npx -y` / `emfirge` / `guide`) and the
   three columns are cramped. Stack it on phones; inline code chips never break inside a word.
6. **How it works, Figure 2 on phones:** the drawing shrinks to a tiny diamond, the "CHANGE 1" label is clipped at
   the left and the fork stack is missing. Make it responsive (stack base/changes and the fork vertically, labels
   inside the frame).
7. **Figure 1 (home and How it works) on phones** is cut at the right; you see half the diagram. Give phones a
   vertical version of the same diagram (changes → emfirge → your agent, top to bottom) that fits 360px with
   readable labels, keeping the same animation.
8. **Tables overflowing at 390** on Security and CLI pages (inside scroll boxes, but with no hint they scroll).
   Prefer stacking like #4/#5; where a table must scroll, show a right-edge fade and keep the first column visible.
9. **`[TODO Ansh: …]` marks are visible on public pages** (e.g. Pricing FAQ, Security). Keep them out of the public
   site and the `.md` files: render them only when the URL has `?todo=1` (or in `next dev`), and keep the full list
   in one place (TODOS in `src/content/site.ts`) so nothing is lost. Where a TODO hides an answer, show a short
   honest line instead (e.g. "Not decided yet.").

## P2: UX and UI polish
10. **Hero on phones:** a large empty gap above the announcement pill; the two buttons have different widths; the
    secondary "Set up, step by step" button shows small green corner fragments that look like a rendering glitch.
    Remove the gap, make both buttons full-width and equal height on phones, and give the secondary button a clean
    1px border (keep the tint).
11. **"Works with" chips** wrap unevenly on phones and are only 23px tall. Make them a tidy row that wraps evenly,
    min 32px tall.
12. **Tap targets** below 32px: footer links (21px), Copy buttons (19px), the footnote ⊞ (10px), "Read more…" /
    "See the sources" / "Read the laws" links (21–22px). Give each at least a 32px hit area (padding, not bigger type).
13. **Tiny and low-contrast text:** up to 14 elements per page are under 11px (mono micro-labels at ~9.5–10px), and
    the muted grey (`rgba(11,16,21,.45)`) is about 3.2:1 on white, below the 4.5:1 needed for small text. Set a
    minimum of 11px for labels and darken muted text used at small sizes to pass 4.5:1. Keep the hierarchy (it can
    still look light).
14. **Consistency pass:** same spacing above/below every H2 section rule, same caption style, same button heights
    across pages, figure frames aligned to the column width on every page.
